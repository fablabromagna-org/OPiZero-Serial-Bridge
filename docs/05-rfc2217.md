# RFC2217 Serial Service

Unfortunately, it doesn't seem possible to use the same serial remote control service for programming and debugging.

The ser2net service doesn't seem to handle the control pins correctly and causes errors when used by remote esptool.

The Espressif esp_rfc2217_server service, on the other hand, works well with remote esptool, but once started, it puts the microcontroller into bootloader mode. This prevents serial monitoring.

While waiting for a more efficient solution, I'm using the two services alternatively (with the drawback of manually performing the switch before and after programming).


## ESP MCU Programming: esp_rfc2217_server

`esptool` includes `esp_rfc2217_server`, an RFC2217 server suitable for remote programming of Espressif devices. It forwards a local serial device over TCP while supporting the serial-control signals used by esptool.

### Install esptool

Use the shared virtual environment because distribution packages are too old to include the RFC2217 server.

```bash
source /opt/custom-env/bin/activate
pip install --index-url https://www.piwheels.org/simple esptool
```

> Note: `piwheels` can provide pre-built ARM wheels. It is optional and may not support every architecture or package version.


Confirm the target serial device to use before exposing it:

```bash
ls -l /dev/ttyUSB* /dev/ttyACM*
```

### Start the Server

For a USB serial adapter at `/dev/ttyUSB0`, listen on TCP port 4000:

```bash
source /opt/custom-env/bin/activate
esp_rfc2217_server -p 4000 /dev/ttyUSB0
```

Only one process should control the physical serial port at a time. OliveTin can be used to start this command on demand; see [OliveTin Dashboard](06-olivetin.md).

### Connect from a Remote Workstation

Read the target chip identifier with esptool:

```bash
esptool --port "rfc2217://192.168.10.54:4000?ign_set_control" chip_id
```

PlatformIO can use the same endpoint:

```ini
upload_port = rfc2217://192.168.10.54:4000
```


## Serial Monitoring with ser2net

Install `ser2net` from the distribution repository:

```bash
apt install ser2net
```

The reference setup does not run `ser2net` as a permanent system service because it would keep the serial device open and prevent `esp_rfc2217_server` from using it. A static YAML configuration would also be too restrictive because the USB serial device may change.

Instead, start `ser2net` on demand, optionally through OliveTin, and provide the connection configuration on the command line with `-Y`:

```bash
USB_PORT=$(ls /dev/ttyUSB* | head -n 1)

exec ser2net -n -d \
  -Y "connection: &esp" \
  -Y "  accepter: telnet(rfc2217),tcp,4000" \
  -Y "  connector: serialdev,${USB_PORT},115200n81,local"
```

This example automatically selects the first available `ttyUSB` device and is intended primarily to demonstrate the `-Y` option. The OliveTin action should instead pass a serial device selected from a predefined list.

Only one service can use the serial device at a time. Stop `esp_rfc2217_server` before starting `ser2net`, and stop `ser2net` before programming the MCU.

Connect to the server with Netcat for a raw terminal session:

```bash
nc 192.168.10.54 4000
```

Alternatively, use pySerial's RFC2217 client:

```bash
python3 -m serial.tools.miniterm \
  "rfc2217://192.168.10.204:4000?ign_set_control" 115200
```

Replace the example IP address and baud rate with the values required by the target system.
