# RFC2217 Serial Service

`esptool` includes `esp_rfc2217_server`, an RFC2217 server suitable for remote programming of Espressif devices. It forwards a local serial device over TCP while supporting the serial-control signals used by esptool.

## Install esptool

Use the shared virtual environment because distribution packages is too old to include the RFC2217 server.

```bash
source /opt/custom-env/bin/activate
pip install --index-url https://www.piwheels.org/simple esptool
```

> Note: `piwheels` can provide pre-built ARM wheels. It is optional and may not support every architecture or package version.


Confirm the target serial device before exposing it:

```bash
ls -l /dev/ttyUSB* /dev/ttyACM*
```

## Start the Server

For a USB serial adapter at `/dev/ttyUSB0`, listen on TCP port 4000:

```bash
source /opt/custom-env/bin/activate
esp_rfc2217_server -p 4000 /dev/ttyUSB0
```

Only one process should control the physical serial port at a time. OliveTin can be used to start this command on demand; see [OliveTin Dashboard](06-olivetin.md).

## Connect from a Remote Workstation

Read the target chip identifier with esptool:

```bash
esptool --port "rfc2217://192.168.10.248:4000?ign_set_control" chip_id
```

PlatformIO can use the same endpoint:

```ini
upload_port = rfc2217://192.168.10.248:4000
```

For an interactive terminal, use pySerial's miniterm:

```bash
python3 -m serial.tools.miniterm "rfc2217://192.168.10.204:4000?ign_set_control" 115200
```

Test reset and boot-mode behavior with the exact USB serial adapter and target board. Signal wiring and driver behavior vary by hardware.

## ser2net Alternative

`ser2net` can expose serial ports through RFC2217 for general console use. In the reference setup it was not reliable for Espressif flashing, likely because reset and boot-mode control signals were not handled as required. Use `esp_rfc2217_server` for esptool programming unless the alternative has been validated with the target hardware.
